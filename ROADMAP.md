# Roadmap

## What's next on the road to 1.0

- **Pilot adoption + feedback.** First-party adopters running on `0.1.0-pre.x` for at least one full release cycle. Their pain points drive the API decisions that get locked at 1.0.
- **Public API stability gate.** Tag every exported symbol `@public` or `@internal`, wire `@microsoft/api-extractor` (or equivalent) into CI so any unintended surface change blocks merges.
- **Third-party cryptographic audit.** External review of the key hierarchy, envelope format, AES-KW wrapping, and PBKDF2 parameters. Required before a 1.0 stamp.
- **Bundle-size CI gate.** Pin the floor + per-subsystem allowances in `bundle-manifest.json`; CI fails on any unexplained regression.
- **Showcase + recipe coverage.** A runnable end-to-end test for every `with*()` strategy and every storage destination so adopters pick a backend by reading working code.
- **`by-*` session-share family.** `@noy-db/by-peer` (WebRTC, renamed from `@noy-db/p2p`) and `@noy-db/by-tabs` (BroadcastChannel multi-tab sync) shipped together with the family debut. Next: `@noy-db/by-server` (WebSocket / SSE relay) and `@noy-db/by-room` (Liveblocks / Yjs y-websocket).

## Recently shipped (and what's deferred)

The following capabilities are now in main:

- **Guards + Derivations subsystems (v0.1.0-pre.11).** Two new write-path primitives land in the same release, plus tier-2 auth showcase coverage.
  - **`withGuard`** ([#123](https://github.com/vLannaAi/noy-db/issues/123)) — record-level lock + field-level freeze + role-gated amendment invariant, dispatched inside `Collection.put` / `.delete`. Amendments write a dedicated `op: 'amendment'` ledger entry; `verifyBackupIntegrity` and `reconstructAtVersion` skip them when reconstructing the canonical record stream. Four error classes: `RecordLockedError` / `FieldFrozenError` / `InvariantError` / `AmendmentForbiddenError`. Cross-collection invariants get a `ReadOnlyVaultFacade` for sibling reads. New `@noy-db/hub/guards` subpath. (#123, #124, #125, #126, #127, #128)
  - **`withDerivation`** ([#129](https://github.com/vLannaAi/noy-db/issues/129)) — Dim 14 v1. Deterministic source → outputs with eager dispatch on `Collection.put` + lazy resolution on `Collection.get`. `computeStrategyHash` (SHA-256 over source + sorted outputs + derive.toString()) detects drift; `DerivationRegistry` runs DFS cycle detection at vault open. `vault.deriveAll(collection)` provides the bulk recompute primitive. Four error classes: `DerivationCycleError` / `DerivationDepthError` / `DerivationOutputUnknownError` / `DerivationOutputShapeError`. New `@noy-db/hub/derivations` subpath. (#129)
  - **Tier-2 auth showcases** ([#77](https://github.com/vLannaAi/noy-db/issues/77), [#78](https://github.com/vLannaAi/noy-db/issues/78)) — closes both `priority: high` real-provider gaps. Showcase 71: `on-password` capability matrix (16 scenarios pinning the `kek: null` keyring security contract). Showcase 72: `on-webauthn` Playwright virtual authenticator with real Chromium CDP + PRF support (5 scenarios).
  - **Reviewer-caught side-fixes** — `verifyBackupIntegrity` + `reconstructAtVersion` amendment-skip (would have falsely failed integrity on any vault with amendment entries); `ReadOnlyVaultFacade` exposed to amendment invariants (was a `null` / `[]` stub blinding cross-collection reads); cache-invalidation fix in `putManyAtomic` revert path; `runTransaction` `executed.push(...)` reorder (mid-put throws now correctly trigger rollback).
  - **Known follow-ups for pre.12** — bundle-size regression ~30–48% gz introduced by the guards `index.ts` re-export ([#130](https://github.com/vLannaAi/noy-db/issues/130)); `withDerivation` pre-hashed register so `register()` becomes sync ([#132](https://github.com/vLannaAi/noy-db/issues/132)); strict-mode multi-output orphan window ([#133](https://github.com/vLannaAi/noy-db/issues/133)).
- **Audit-and-cleanup batch (v0.1.0-pre.10).** 20 PRs addressing 18 issues from a 2026-05-09 deep-review of the pre.9 surface. Highlights: STRICT_POLICY `enroll-user` / `revoke-user` gates wired through `db.grant` / `db.revoke` ([#79](https://github.com/vLannaAi/noy-db/issues/79)); `db.changeSecret` validates passphrase strength by default ([#80](https://github.com/vLannaAi/noy-db/issues/80)); `grant()` rejects when caller's `kek` is null ([#81](https://github.com/vLannaAi/noy-db/issues/81)); `onInvalidKey: 'reset'` no longer destroys valid keyrings on partial corruption ([#82](https://github.com/vLannaAi/noy-db/issues/82)) — the audit's highest-impact P0; passphrase canary closes the single-DEK + all-DEKs-corrupt ambiguity ([#113](https://github.com/vLannaAi/noy-db/issues/113)); `rotatePassphrase` slot ceremony validates `wrapKind` ([#83](https://github.com/vLannaAi/noy-db/issues/83)); subpath barrels populated for `team/` / `i18n/` / `query/` / `session/` / `bundle/` / `store/` ([#90](https://github.com/vLannaAi/noy-db/issues/90)).
- **Consumer iteration cycle (v0.1.0-pre.9).** Closes the 5-issue follow-up surfaced after the first production consumer shipped pre.8. No new subsystems; surgical extensions to APIs that landed in pre.8.
  - `db.updateUser(vault, options, factors?)` — post-grant identity mutation for `role` / `displayName` / `permissions` ([#54](https://github.com/vLannaAi/noy-db/issues/54)). Pure plaintext-header rewrite (no DEK rewrap, no KEK required). New `update-user` policy gate. Two-sided role-elevation guard mirrors `db.grant`'s hierarchy.
  - `db.updateAuthenticator(vault, slotId, options, factors?)` — meta-only mutation for slot rename / label changes ([#55](https://github.com/vLannaAi/noy-db/issues/55)). Anti-slot-swap is structural: `UpdateAuthenticatorOptions` only carries `meta`, so wrap material / id / method are unreachable through this entry point. New `update-authenticator` policy gate.
  - `webAuthnSlotRewrapCeremony` from `@noy-db/on-webauthn` ([#56](https://github.com/vLannaAi/noy-db/issues/56)) — fills the placeholder in #29's `slotCeremonies` API. Single ceremony, two crypto operations under one assertion: decrypt OLD payload + encrypt NEW payload with `ctx.newDeks` under the same wrapping key. Closes the "rotate phrase without losing my biometric" UX promise. Helper lives in on-webauthn (NOT hub) per the peer-dep convention.
  - `UserApi.updateMe<T>(patch)` accepts `null` to clear fields ([#57](https://github.com/vLannaAi/noy-db/issues/57)). Matches lodash `_.merge` and Firestore `FieldValue.delete()`. New `DeepPartialOrNull<T>` type.
  - `@noy-db/on-magic-link` `acceptInvite` forwards `passphrasePolicy` to the inner `keyringRotatePassphrase` ([#53](https://github.com/vLannaAi/noy-db/issues/53)) — unblocks consumers using non-default phrase shapes (Thai/EN-mixed, hyphen-separated, BIP-39 word lists).
- **Auth-review batch (v0.1.0-pre.8).** Closes the 12-issue auth-review filed by the first production consumer. Highlights:
  - `db.recoverUser(vault, options, factors?)` — atomic peer-recovery primitive ([#33](https://github.com/vLannaAi/noy-db/issues/33), [#34](https://github.com/vLannaAi/noy-db/issues/34)). Single `store.put` rewraps a target user's keyring under a fresh temp passphrase. Owner→owner natively allowed (closes #33's hard block); gated by new `peer-recover-user` policy gate. No key rotation, identity preserved.
  - `db.rotatePassphrase` accepts opt-in `slotCeremonies` map preserving tier-2 slots across rotation ([#29](https://github.com/vLannaAi/noy-db/issues/29)) — closes the "yearly rotation wipes my biometric" UX cliff. Anti-slot-swap guard validates `id` + `method` match.
  - `db.recoverPassphrase` auto-rotates remaining recovery codes ([#36](https://github.com/vLannaAi/noy-db/issues/36)) — defaults to `rotateRemainingCodes: true`. Returns `{ newCodes }` for the UI to show once.
  - **Tier-2 wrap-DEKs unification** ([#26](https://github.com/vLannaAi/noy-db/issues/26) Path C) — `KeyringAuthenticator` becomes a discriminated union with `wrapKind: 'kek' | 'deks'`. Unifies tier-0 (paper recovery) / tier-2 (`@noy-db/on-password`) / tier-3 (`@noy-db/on-pin`) around the wrap-DEKs primitive.
  - `@noy-db/on-magic-link` invite + peer-recovery primitives ([#32](https://github.com/vLannaAi/noy-db/issues/32)) — `issueInvite` / `acceptInvite` / `revokeInvite` / `issuePeerRecovery`. URL-fragment transport, single-use semantics, audit log, revoked-link-shadow-keyring defense.
  - `FactorKind` extended with `webauthn-platform` / `password` / `pin` ([#30](https://github.com/vLannaAi/noy-db/issues/30)). `PassphrasePolicy` `pattern` / `customValidator` escape hatches ([#31](https://github.com/vLannaAi/noy-db/issues/31)) unblock Thai/EN-mixed phrases.
  - Public `mintPaperRecoveryEntry` + `unwrapDeksFromPaperEntry` + `db.getKeyring` ([#28](https://github.com/vLannaAi/noy-db/issues/28), [#39](https://github.com/vLannaAi/noy-db/issues/39)). Shared `WrappedDeksBlob` primitive ([#44](https://github.com/vLannaAi/noy-db/issues/44)) — one canonical wrap-DEKs implementation across tiers. `UnlockedKeyring.kek` tightened to `CryptoKey | null` ([#41](https://github.com/vLannaAi/noy-db/issues/41)).
  - `docs/subsystems/auth-landscape.md` ([#45](https://github.com/vLannaAi/noy-db/pull/45)) — reference map of every authentication, unlock, and sealing-key primitive scored on offline-first dimensions.
- **Per-principal user envelope (`vault.user.*`, v0.1.0-pre.6).** Every keyring gets a `_users/<keyringId>` envelope encrypted under a shared `_users` DEK; hub owns plumbing (storage, sync, history, lifecycle, encryption), apps own schema. Three method families: write-self (`me/updateMe/setMe` — own-only write rule, structural), read-anyone (`get/list` gated by `view-team-profiles`), reactive (`subscribe/live`). New built-in policy gates `edit-own-profile` (default `minTier: 3`) and `view-team-profiles` (default `minTier: 2`). `db.grant({ initialProfile: T })` admin pre-fill at invite time; cascade-revoke deletes envelopes alongside keyrings. Joined enumeration via `listUsersWithEnvelopes()` for admin UIs. See `docs/subsystems/user-envelope.md`.
- **`db.enrollWebAuthn()` and `db.lockVault()` (v0.1.0-pre.6).** Two infrastructure unblockers for the niwat consumer: native WebAuthn enrollment with the real internal keyring (no synthetic-keyring workaround), and a soft-lock that preserves QuickUnlock state (PIN resume after lock-screen UX).
- **Vault diff utility** (`diffVault`) — primitive  used by every `as-*` reader and any consumer-side preview UI.
- **Slice export of `.noydb` bundles** — `collections` allowlist + `since` envelope cutoff.
- **Multi-recipient re-keyed `.noydb` bundles** — `exportPassphrase` shorthand and `recipients[]` with per-slot ACL.
- **Import family phase 1** — `fromString` / `fromBytes` for `as-csv` / `as-json` / `as-ndjson` / `as-zip`, returning an `ImportPlan` with `merge | replace | insert-only` policies.
- **WinZip-AES-256 password on `as-zip`** — implementation strictly to spec; cross-tool interop validation pending.
- **Import family phase 2** — `as-blob` `fromBytes`, `as-xml` `fromString`, `as-xlsx` `fromBytes` reader; symmetric with phase 1 ImportPlan shape.
- **Import capability gate** — `ImportCapability` keyring extension + `vault.assertCanImport(tier, format?)`. Default-closed for every role on every dimension; owners must positively grant.
- **Atomic apply** — `ImportPlan.apply()` inside `vault.noydb.transaction(...)`. Partial failure rolls back via `runTransaction`'s revert pass; opt-in via `withTransactions()` strategy.
- **Per-recipient bundle expiry** — `recipients[].expiresAt`. Past-cutoff slot throws `KeyringExpiredError` before DEK unwrap (no passphrase-timing leak).
- **Bundle record-level filters** — `where` predicate and `tierAtMost` ceiling on `writeNoydbBundle`. Plaintext pre-pass; survivors carry their original ciphertext (no re-encrypt, zero-knowledge clean).

Deferred sub-issues open at `priority: low` for the next cycle:
- ledger-aware slice (drops collection cleanly when history is on) — **blocked on design RFC**: refuse-when-history-present vs allow-divergent-head with `slicedFrom` metadata
- per-import ledger-entry tagging (`reason: 'import:<format>'`) — scope larger than initial estimate; needs `LedgerEntry` shape change + `Collection.put` option threading + canonical-JSON hash chain test pin
- WinZip-AES interop validation matrix against 7-Zip / Archive Utility / WinRAR — manual cross-tool testing, not a code task

No version-numbered milestones until `0.1.0` — the pre-release is intentionally a single rolling target.
