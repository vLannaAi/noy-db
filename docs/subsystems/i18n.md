# i18n

> **Subpath:** `@noy-db/hub/i18n`
> **Factory:** `withI18n()`
> **Cluster:** D — Data Shape
> **LOC cost:** ~854 (off-bundle when not opted in)

## What it does

Multi-locale records via two complementary patterns: `dictKey` (stable enum-like keys → shared label dictionary) and `i18nText` (per-record free-form text in multiple locales). Locale resolution happens at read time. Dictionary itself is encrypted and versioned.

## When you need it

- Apps that ship in more than one language
- Enum-like fields (`status`, `taxClass`, `country`) where labels differ by locale
- Per-record translatable content (descriptions, comments, free-form notes)
- Auto-translate hooks for missing locale fills

## Opt-in

```ts
import { createNoydb, dictKey, i18nText } from '@noy-db/hub'
import { withI18n } from '@noy-db/hub/i18n'

const db = await createNoydb({
  store: ...,
  user: ...,
  i18nStrategy: withI18n(),
})

const vault = await db.openVault('firm')
await vault.dictionary('status').putAll({
  draft: { en: 'Draft', th: 'ฉบับร่าง' },
  paid:  { en: 'Paid',  th: 'ชำระแล้ว' },
})

vault.collection<Invoice>('invoices', {
  dictKeyFields: {
    status: dictKey('status', ['draft', 'paid'] as const),
  },
  i18nFields: {
    description: i18nText({ languages: ['en', 'th'], required: 'all' }),
  },
})
```

## API

- `vault.dictionary(name).putAll(...)` / `put(...)` / `get(...)` / `delete(...)` / `list()` / `rename(...)`
- `dictKey(name, keys)` and `i18nText({ languages, required })` field descriptors
- `resolveI18nText(value, locale, fallback?)` helper — resolve a single value
- Per-call `{ locale, fallback }` on `collection.get()` / `list()` / `query()` reads

## Behavior when NOT opted in

- `applyI18nLocale` (under the hood) returns the record unchanged — locale resolution is silently skipped
- `validateI18nTextValue` throws when a collection declared `i18nFields` (misconfiguration: declared but didn't opt in)
- `vault.dictionary(name)` throws with a pointer to `@noy-db/hub/i18n`

## Hardening (per-layer policy, substitute, script, dictKey parity)

Optional, opt-in extensions on `i18nText()` / `dictKey()`. Fields that
don't set them behave exactly as before (zero breaking change). Full
design: `docs/superpowers/specs/2026-06-05-i18n-multilingual-field-hardening-design.md`.

**`onMissing` + `substitute` — missing-locale policy.** When a field is
resolved to an absent locale, `onMissing` decides: `'substitute'` (walk
the declared `substitute` chain, then `null`), `'null'`, or `'throw'`
(the default — today's behavior). `onMissing` may be a scalar or a
per-layer map (`read`/`guard`/`join`/`mv`/`derivation`/`export`); the
`guard` layer defaults to lenient `'substitute'`. A caller-supplied
`fallback` at read time overrides the declared `substitute`.

```ts
i18nText({
  languages: ['th', 'en'], required: 'any',
  substitute: ['en', 'th', 'any'],
  onMissing: { read: 'substitute', mv: 'throw', derivation: 'null' },
})
```

> **Current wiring:** the `read` (`get`/`list`), `guard`, `derivation` and
> `mv` layers are enforced — guard / derivation `ctx.vault` reads resolve under
> their own layer policy (`guard` defaults to the lenient `'substitute'`). The
> `mv` layer fires for **UNION** materialized views that declare
> `{ i18nLocale, i18nFields }`: group-key i18n fields resolve at the `mv` layer
> before bucketing, so buckets are stable strings (grouping a raw i18n field
> without a locale throws `LocaleNotSpecifiedError` — group by a `dictKey`/
> `staticDict` code instead, and resolve the label at read). i18n fields merely
> *carried through* an MV stay raw — declare them on the **output collection**
> and they resolve per-reader at read time. The **`join` layer** resolves a
> joined right-side i18n field to the query locale —
> `query().join(...).toArray({ locale })` (or the vault default; raw when
> locale-less). Still **not wired**: the `export` layer and query-form MV
> grouping (a `Query`'s own `groupBy` carries no locale channel) — tracked
> follow-ups (#285 + export,
> milestone #18). Design: `docs/superpowers/specs/2026-06-13-i18n-mv-join-layer-design.md`.

**Script enforcement (`script`, `onScriptViolation`).** Write-time
per-locale validation. `script: 'auto'` infers allowed Unicode scripts
with **asymmetric Latin tolerance**: non-Latin locales also allow
`Latin` (so `'9/9 อาคาร TCM ถนนรัชดาภิเษก'` passes), while Latin locales
reject other scripts (so Thai text in an `en` slot is rejected).
`Common`/`Inherited`/`Mark` (digits, combining marks) are always
allowed. Violations `'reject'` (default, `ScriptViolationError`),
`'filter'` (strip), or `'warn'`. Tighten a field with an explicit set:
`script: { th: ['Thai'] }`.

**`I18nMap<Langs, Required>` type helper.** Types the stored locale-map
from the `required` mode so the compiler forces you to handle an absent
optional locale (`string | undefined`) instead of silently reading
`undefined` — the right fix for bare `.th` access at raw-reading
(identity/guard/export) layers. `'all'` (default) → every locale
required; `'any'` → every locale optional; `readonly L[]` → listed
required, rest optional.

```ts
type Lang = 'th' | 'en'
interface Contact {
  name: I18nMap<Lang, 'any'>        // { th?: string; en?: string }
  legalName: I18nMap<Lang, ['th']>  // { th: string; en?: string }
}
```

**dictKey parity.** `dictKey()` accepts the same `onMissing`/`substitute`
(default stays `'null'` = legacy omit-on-miss). An **array-of-keys**
field resolves to `[{ key, label }]` pair objects; a **wildcard path**
(`contacts[].title`) adds a per-element sibling `<leaf>Label`. The
stable key is preserved through resolution, so identity operations
(`groupBy`, dedup) bind to the key even when labels collapse across
locales (`Mr.`/`Ms.` → `คุณ`).

## staticDict (code-provided dictionary)

`staticDict(name, table, opts?)` is a sibling to `dictKey` for **closed,
defined-in-code, identical-across-vaults** enums (honorific, civil-status,
gender, religion, status…). The labels live in the in-code `table`; the record
stores only the stable **code**. Drop it into the same `dictKeyFields` slot:

```ts
const workers = vault.collection<Worker>('workers', {
  dictKeyFields: {
    department:  dictKey('department', ['ops', 'fin'] as const),  // per-vault, editable
    civilStatus: staticDict('civilStatus', {                      // code-defined
      adultMale:   { th: 'นาย',    en: 'Mr'  },
      adultFemale: { th: 'นาง',    en: 'Mrs' },
    }, { displayLocale: 'th' }),
  },
})

await workers.put({ id: 'w1', civilStatus: 'adultMale' }) // stores only the code
await workers.get('w1')                  // locale-less vault → civilStatusLabel: 'นาย'
await workers.get('w1', { locale: 'en' }) // → civilStatusLabel: 'Mr'
```

How it differs from `dictKey`:

- **No `_dict_*` collection** and **no `rename()`** — labels are code constants,
  so there is no per-vault encrypted copy and no O(records) migration. A label
  change is a code deploy.
- **Hybrid resolution.** With a configured `displayLocale`, a `<field>Label`
  resolves even under a **locale-less** read — the property a locale-less app
  needs and `dictKey` cannot provide. Without `displayLocale` it behaves like
  `dictKey` (no label until a locale is active). When a locale *is* active, it
  honors `onMissing`/`substitute` exactly like `dictKey`. The locale gate is
  otherwise unchanged: an `i18nText`-only or plain-`dictKey` collection still
  returns the raw record on a locale-less read.
- **Read-only by construction.** `vault.dictionary(staticName)` throws
  `StaticDictReadonlyError` — a static dict has no mutation surface.
- **Put-time code validation.** A stored code outside `table` throws
  `UnknownDictCodeError` (opt out per descriptor with `{ validateCodes: false }`).
- **Query parity.** `groupBy(field)` buckets by the stable code; the
  code-table-backed source resolves `{ by: 'label' }` at the active locale, or
  `displayLocale` when the query is locale-less.

Migrating from a userland helper needs **zero record change** — the record
already stores the code; only the field descriptor changes. (#291)

## Pairs well with

- **aggregate** — `groupBy(dictKeyField)` resolves labels in the result on render
- **history** — locale changes are versioned

## Edge cases & limits

- Required locales declared in `i18nText({ required: 'all' })` are enforced on put — missing translations throw `MissingTranslationError`
- `'auto'` translate fields call out to the `plaintextTranslator` callback set at `createNoydb`-time
- Dictionary `rename()` rewrites every collection record that points at the old key — O(records) per rename
